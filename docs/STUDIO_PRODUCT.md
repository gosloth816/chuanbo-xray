# 齐鲁卖点与传播X光融合方案

主流程：图片和介绍 → AI识别建议 → 商家确认事实 → 选择受众及渠道 → 模型生成 → 人工编辑留痕 → 发布前核对 → 审核报告。

## 人机分工

模型整理信息和生成候选文案；商家负责核对所有字段、补充依据、保存修改并作最终发布决定。图片只帮助识别直接可见内容，不能据此推断甜度、产地、认证和功效。模型输入明确将用户资料视为待处理数据，程序校验返回格式、渠道与引用事实编号；这些检查不能消除全部模型错误。

事实变更后，旧文案禁止直接继续生成或送审。生成记录保存当时的事实快照、输入指纹、模型名、提示词版本、目标受众、文案及修改前后记录。图片仅在当前会话中处理，生成记录只保留其指纹，不存图片原始字节。公开部署时上传内容进入托管服务器，远程模型启用时另发至已配置服务；界面分别说明。

## 传播X光怎样融合

“一键送至传播X光”把保存后的文案作为宣传材料、确认字段作为参考资料创建审核会话。交接记录保留创作ID、生成来源和人工修改事件。传播X光使用现有规则检索与人工复核，不冒充新增AI审核。

原有文档上传、公开来源案例、人工复核、HTML/Markdown/JSON报告与SQLite记录均保留。侧栏选择“传播X光审核”即可独立使用，xray_app.py为原版独立入口。原审核测试现在指向该独立入口；新增测试检查主入口、创作与审核交接。

## 模型状态与训练披露

支持服务器配置的兼容聊天接口和图像输入。本地默认配置仅为服务地址与模型名示例，不代表本机已安装模型。远程接口使用HTTPS、不跟随重定向；只由服务器环境配置地址和密钥，不向网页访客提供任意地址探测功能。

2026年10月31日，公开部署使用qwen3.8-flash完成真实图片识别、多渠道生成、JSON下载与传播X光交接，记录见cloud_real_model_check.json。测试输入为合成商品资料与原创插画，不证明真实商品识别准确率或商家收益。早期本机服务失败记录保留于studio_model_verification.json。合成演示文案是预先编写，不是模型输出；程序测试中的模拟响应只用于测试边界。项目未进行模型训练或微调。

API依据：[百炼图像与视频理解文档](https://docs.bailian.console.aliyun.com/zh/model-studio/vision)。接口地址与可用模型应以配置时的服务商官方说明为准。

## 赛道三交付与不足

相比只有宣传语生成按钮，融合原型增加了事实确认、受众与渠道选择、规则检查、人工修改、可追溯导出及独立审核环节。已有产品说明、可运行原型和本地测试证据；已接通真实多模态服务并完成一次云端全流程测试，仍需真实商品实拍样本、独立使用测试与系统性质量评估。不能据此宣称业务效率已提升、销量已增加或获奖概率已提高。

不需真实企业资料也能先做合成与公开资料可用性测试，但必须区分来源。现有苹果样例与插画为原创合成内容，没有真实品牌或企业授权声明。旧版公开来源材料仅在传播X光案例中保留，不作为苹果商品的依据或训练集。


## 商品资料与生成方式分别标记

生成记录区分“预先编写的演示文案”和“实际模型调用”，另用synthetic_input记录输入是否为合成或测试商品。即使模型真实生成了文案，只要商品为合成测试资料，界面、Markdown及传播X光报告都保留合成材料标识。商品资料页提供显式标记，内置演示自动保留该标记。对应自动测试覆盖真实生成来源与合成输入同时存在时的交接。

## 文案创作1.1

从单句参数复述改为按渠道组织开场、场景、事实展开与行动引导；默认完整成稿，也可选精简短稿。商家可设置创作目标、主推已确认事实与表达方向。表达方向单独传入，不成为产品事实；创作要求随记录导出并交接审核。生成使用独立的创作采样参数和4096 Token输出上限，识别保留较低随机性与2048 Token上限。生成篇幅是写作目标，不是硬性质量保证；引用编号仍需人工核对。
