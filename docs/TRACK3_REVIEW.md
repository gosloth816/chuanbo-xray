# 传播 X 光：赛道三评价与改进

2026-10-31，依据用户补充的比赛通知、作品要求和答疑；这是项目审查意见，不是官方评分。原误传大创文件不再作为参赛依据。

## 判断

方向适合赛道三，建议继续以“山东农业科技与植保产品宣传发布前审核”为切入点。它聚焦一个清楚的传播决策：哪些效果主张有依据、缺什么条件、哪些需要补证或删除。无需扩展成全链路营销平台。

项目优势是可运行的审核流程、文件与段落定位、可编辑人工意见、多格式报告和操作留痕。相较普通聊天式点评，这些更容易让评审独立验证，也对应正式要求中的功能可用性和人机协作。

最大短板有两项：**真实模型尚未跑通、真实业务改善尚未测量**。不能只凭开发中使用Codex，就宣称已证明运行时大模型工具的能力。规则演示可作可靠性补充，但建议在提交前提供至少一次真实模型参与主张提取和证据分析的完整记录。真实小范围反馈属于明确的酌情加分项，目前尚无此证据。

## 本次代码改进

- 保留上轮复核完整性检查，统一展示草稿、待处理及复核记录完整状态；这些状态不是发布批准。
- 增加实际程序分析耗时、复核进度、引用校验分子分母、无证据主张数和人工改判数。界面显示主要指标，HTML/Markdown显示运行摘要，JSON保留完整指标。

## 如何补齐业务价值

先邀请3—5名能够理解此类材料的试用者，用已授权或明确标注的合成材料做可用性试点；合成试点只能说明操作表现，不冒充真实业务反馈。之后争取至少一位实际宣传或审核岗位人员测试授权材料。

每人对难度接近的两份材料分别纯人工审核和使用工具审核，轮换顺序，避免重复材料造成记忆偏差。记录总审核用时、主张漏检数、证据位置错误、最终修改意见、是否独立跑通及失败步骤。原始记录包含材料ID、试用者匿名编号、审核方式、开始结束时间、样本性质、问题和反馈。由独立复核者检查结果质量，不用系统结论作为正确答案。

价值预期可写为：“希望降低证据定位用时，同时控制遗漏和误放行；目标须经试点验证。”若采用例如20%的用时下降作为团队目标，必须明确是目标，不能写成已实现结果。程序分析耗时不含人工判断，引用逐字存在也不能证明资料真实或充分。

## 模型运行验证

在本机启动兼容服务、确认模型名后运行：

```powershell
.\.venv\Scripts\python.exe scripts\verify_local_model.py --base-url http://127.0.0.1:11434/v1 --model qwen2.5:3b
```

该名称仅为现有默认配置，不表示已安装或验证。脚本只发送内置合成材料，成功后保存真实会话、模型名、提示词版本、原始资料、结果及耗时。随后在应用中启用模型、测试连接、选择大模型分析模式，完成一次人工复核并导出报告。最终证据应覆盖真实模型运行和人工干预，而不仅是连接成功。

本地模型适合保护授权材料隐私，但评审电脑没有相应服务时只能运行规则模式。需准备已配置好模型的演示环境，或后续接入经授权且可供评审访问的模型服务。当前公开网页只提供规则演示，因此尚不能据此宣称评审可以独立完成大模型流程。
