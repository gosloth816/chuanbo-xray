# AI 大模型应用说明文档

**项目名称：传播 X 光**  
**参赛赛道：赛道三·AI 传播工具创新**  
**应用名称：农业科技产品宣传材料诊断与证据核验工具**  
**文档版本：2.0**  
**更新日期：2026 年 10 月 27 日**

## 一、项目与 AI 使用概述

传播 X 光面向山东农业科技企业和植保产品企业的市场宣传、材料审核场景，帮助用户在宣传材料发布前核查宣传主张是否有上传资料支持、是否遗漏试验条件、是否存在资料冲突，并把系统判断交给人工确认。项目不生成虚假产品效果，也不自动判定宣传违法或造假。

项目开发过程中使用了 Codex 辅助编写代码、生成测试草稿、整理文档结构和检查界面实现。团队需要确定业务目标、判断类别、证据规则、测试意图和最终验收标准，并对所有代码、测试数据和文档进行人工审查。AI 不是项目事实来源，开发 AI 生成的代码或文字不能替代团队对真实业务、法律和产品信息的核实。

应用运行时默认采用本地规则核验模式，不调用外部大模型、不需要 API 密钥，也不产生付费调用。只有在用户自行启动本机模型服务并主动启用时，程序才会连接 localhost / 127.0.0.1 / ::1 的本机接口。代码会拒绝远程地址，避免宣传材料离开本机。

## 二、使用到的 AI 工具与环节

| 工具或能力 | 使用环节 | 实际用途 | 结果处理方式 |
| --- | --- | --- | --- |
| Codex | 开发阶段 | 辅助生成 Python 代码、Streamlit 界面、测试草稿和文档初稿 | 团队检查、运行测试并修改后再纳入项目 |
| 本地规则引擎 | 默认运行阶段 | 文档分块、关键词检索、数值核对、限制语提示和风险分类 | 所有结果附检索证据，并由引用校验和人工复核约束 |
| 可选本机大模型 | 增强运行阶段 | 可辅助提取宣传主张、分析候选证据并给出判断建议 | 仅允许本机地址；引用必须逐字存在于原文；模型失败直接报错 |

当前开发环境中没有可用的本机大模型服务。因此，本说明不会声称大模型增强路径已经完成实际端到端调用验证。已经验证的是：本机地址限制、模型响应 JSON 结构解析、引用候选约束、错误处理和离线完整业务流程。

## 三、运行时人机协作模式

### AI 或程序负责

1. 解析用户上传的 TXT、MD、PDF、DOCX 文本；
2. 按段落或页码切分材料，保留来源定位；
3. 从宣传文本中提取可能具有可核验内容的句子；
4. 检索产品说明、技术报告或试验资料中的候选证据；
5. 比较数值、绝对化表达、试验范围和限制性表述；
6. 对系统展示的引用做原文逐字校验；
7. 生成初步判断、理由和修改建议；
8. 记录模型名称、运行模式、提示词版本和审核操作。

### 人工负责

1. 确认宣传材料和产品资料是否完整、合法、真实；
2. 判断系统检索到的证据是否与宣传语境真正相关；
3. 确认、修改或驳回系统判断；
4. 填写修改理由和最终发布表述；
5. 决定是否补做试验、检测、登记或专业审查；
6. 对最终发布材料承担责任。

### 程序强制边界

- 没有检索到证据时输出“证据不足”，不会输出“虚假”或“违法”；
- 引用必须在原文中逐字找到，不能只给出类似说法；
- 模型调用失败时直接提示失败，不生成固定文案冒充成功；
- 每个系统判断都必须显示人工复核入口；
- 人工修改和理由写入本地操作留痕；
- 报告明确写明其不构成真实性、合法性或合规性结论。

## 四、提示词与流程版本

当前提示词/流程版本：`xray-claim-review-v2.2`。

大模型增强路径由两个环节组成：

1. **宣传主张提取提示词**：要求只提取宣传原文中可核验的完整句子，不得生成新文案；程序会再次检查模型输出的主张是否能在宣传原文中逐字定位，否则终止分析。
2. **证据分析提示词**：只向模型提供检索到的候选原文，要求其只能依据候选证据判断，引用必须逐字摘录，并从支持、条件支持、证据不足、资料冲突、待人工核验五类中选择。程序随后再次验证证据编号与引用文本，引用校验失败时转为待人工核验。

离线规则路径不调用大模型。它使用关键词检索、数值和单位、限制语、绝对化表达及候选证据中的否定性内容进行可解释的风险提示。规则路径的局限会在界面和报告中明确显示。

## 五、AI 使用披露与真实性说明

- 三个内置案例均为团队为测试流程设计的**合成测试数据**，文件内和界面中均明确标注“不对应任何真实产品、企业、试验或论文”。
- 合成案例的人工参考答案由团队为验证规则而设计，只用于检查软件在受控输入下的行为，不作为真实行业数据。
- 项目没有虚构用户反馈、真实企业访谈、真实试验结果或推广效果。
- 项目没有购买或使用付费模型服务，没有设置充值、订阅或付费入口。
- 项目代码和界面资源会按要求推送到 GitHub 公共仓库，并由 Streamlit Community Cloud 托管公开演示。
- 本地运行时材料只在当前电脑处理；云端公开演示时，上传材料会发送到托管服务器，页面会提示不要上传敏感或未获授权的真实商业材料。
- 云端实例的运行记录存放在临时目录，实例重启后可能被清除。
- 当前测试结果来自实际运行的自动化测试和合成评估脚本，原始记录保存在 `docs/verification.json` 与 `docs/evaluation_results.json`。

## 六、风险与限制

本地规则模式对同义改写、复杂否定、跨段落推理和图表信息的处理能力有限。扫描版 PDF 与海报图片在没有可提取文字或人工转写时不会被识别，系统也不会猜测内容。即使未来启用本地大模型，模型仍可能误判、遗漏或作出不适当概括，因此必须保留人工复核。

本工具只辅助审核宣传材料与上传资料之间的关系，不核验资料本身是否真实，不检查完整法规要求，也不替代企业审核、专业判断或法律审查。

## 七、可复查入口

- 应用页面：“关于与验证”；
- 自动测试记录：`docs/verification.json`；
- 合成验证集结果：`docs/evaluation_results.md`；
- 提示词和规则记录：`docs/PROMPT_LOG.md`；
- 操作留痕：应用本地 SQLite 数据库，以及导出报告中的“操作留痕”部分。
