# 公开资料与参赛强化说明

## 没有自有数据是否还有意义

有。传播 X 光是核对用户材料与证据的工具，不是从零训练的农业预测模型。开发阶段可以用合法公开的技术资料验证输入、检索、原文定位、修改和报告流程；真实用户与企业材料决定其业务价值能否成立，后续仍应补充。

本轮已实际下载两份济南市农业农村局公开的2025年技术资料：

1. [2025年小麦春季重大病虫害防控技术方案](https://jnny.jinan.gov.cn/col560/art/2025/art_560_4791419.html)
2. [全国农技中心印发小麦“一喷三防”技术指导意见](https://jnny.jinan.gov.cn/col562/art/2025/art_562_4791421.html)

两份均为同一政府网站转载的全国农技资料，不是两组独立试验，更不是企业授权或合作。原始HTML、抽取文本、获取时间和SHA-256指纹存于 `data/public_sources/`。其他候选网站因访问限制或证书错误未成功下载，未混入数据。未绕过登录、付费墙或关闭证书验证。

公开访问不等于任意商业再分发。资料以保留来源的技术核对演练使用，未确认开放许可证；公开提交前需按赛事对第三方素材的要求复核使用范围。没有使用企业商标、包装图或机构标识，不把资料发布方表述为合作方。2025年资料仅作历史一致性演示，不作为当前生产施药指导。

## 实际接入方式

首页“运行公开资料案例”可直接运行两组案例：

- 技术依据能否证明产品效果：1条真实原文摘录，3条自编压力测试。
- 两份指导意见为何不能混用：4条自编压力测试。

**依据是真实资料，测试文案多数为自编。** 来源性质在界面逐条标明，混合案例仍标记包含合成测试。它们不是网上真实企业宣传案例、不是独立评测集，也不是用户反馈。不存在把编造的宣传归给真实企业的做法。

报告包含公开资料链接、发布时间、获取时间与原始HTML指纹；JSON还保留每份文档的来源元信息。文件指纹验证可发现本地快照变化，不能证明网页内容或技术结论绝对真实。

## 为竞争力做的实际改进

1. 降低评审体验门槛：不用准备材料、登录或联网下载，就能跑通案例。
2. 加入证据层级边界：当资料全部为已标记的通用技术指导时，含“本产品/该产品/这款产品”的主张不能凭词语和数字吻合获得支持。规则与模型路径、人工补充主张都执行同一限制。
3. 拓展农技类主张提取线索，避免遗漏防病虫、防干热风、防早衰等技术描述。该变化仍不能保证所有宣传主张都被提取。
4. 显示失败：8条输入全部提取，6条具体类别与开发参考一致；7条参考风险输入均得到风险提示。两个类别差异如实保留，不把7/7风险提示描述成100%准确率。
5. 应用网页ZIP：读取 Mintlify 与 Linear 设计文档，形成根目录 `DESIGN.md`；减少大块装饰、压缩首页、使用浅色阅读面和细边框，把公开案例放在上传前。保留MIT许可，不复制商标或专属字体。

完整运行结果见 `public_evaluation.md` 与 `public_evaluation.json`，实际导出示例见 `public_case_evidence_scope.html` 和 `public_case_source_difference.html`。合成回归集仍为14/14，单独统计，不与公开依据演练混算。39项自动测试通过。

## 参赛叙事

建议表述：**传播 X 光，让山东农业科技宣传从“说得好”走向“有依据、可复核”。** 先聚焦企业市场和审核人员的一处发布决策，把公共技术背景与特定产品效果证明分开，把机器判断与最终人工决策分开。

答辩用一次具体操作展示：自编文案声称“本产品保证增产30%”，系统检索到公开技术指导，却明确提示它不能证明该产品效果；审核员修改或驳回并说明理由；导出含原文与来源的报告。这个例子体现设计价值，不能当成真实企业问题或真实客户反馈。

## 仍需解决的两项

真实大模型端到端运行仍未完成：本机没有可连接服务，公开演示继续为规则模式。不能用开发时AI辅助替代运行时大模型证据。

真实用户测试仍缺失：邀请3—5位同学先测“能否独立跑通”，记录操作失败，再邀请有实际审核经验者使用授权材料比较耗时和结果。不可用下载资料替代用户反馈，也不可承诺奖项或虚构获奖概率。
